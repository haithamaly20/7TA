# خطة موجهي الضبعة

نظام ويب احترافي متكامل لإدارة خطة الزيارات الشهرية للموجهين التربويين — يعمل كتطبيق **PWA كامل** (قابل للتثبيت، يعمل بدون إنترنت)، مع دعم اختياري لمزامنة البيانات مع **Google Sheets**، وجاهز للنشر المباشر على **GitHub Pages** دون أي إعداد إضافي.

---

## 1) طريقة التشغيل السريع (محلياً)

يعمل النظام بطريقتين:

**أ) بالنقر المزدوج مباشرة (بدون إنترنت وبدون سيرفر):**
1. فك ضغط المجلد.
2. افتح `index.html` بالنقر المزدوج.
3. البيانات تُحفظ تلقائياً في متصفحك (LocalStorage). ميزات PWA (التثبيت، العمل التام دون اتصال عبر Service Worker) تحتاج بروتوكول `http/https`، فلا تعمل عبر `file://` — وهذا سلوك متوقع من متصفحات الويب نفسها، ولا يؤثر على عمل النظام الأساسي إطلاقاً.

**ب) عبر خادم محلي (لتفعيل كل مزايا PWA أثناء التطوير):**
```bash
# داخل مجلد المشروع
python3 -m http.server 8000
# ثم افتح المتصفح على:
http://localhost:8000
```

## 2) رفع المشروع على GitHub وتفعيل GitHub Pages

1. أنشئ مستودعاً جديداً فارغاً على GitHub (بدون README تلقائي).
2. من داخل مجلد المشروع:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO_NAME.git
   git push -u origin main
   ```
3. من صفحة المستودع على GitHub: **Settings → Pages**.
4. تحت **Build and deployment**، اختر **Source: Deploy from a branch**.
5. اختر **Branch: main** و**Folder: / (root)** ثم **Save**.
6. بعد دقيقة أو دقيقتين، سيظهر الرابط المباشر بالشكل:
   `https://USERNAME.github.io/REPO_NAME/`

كل المسارات في المشروع (CSS/JS/الأيقونات) نسبية (Relative)، لذلك يعمل المشروع مباشرة سواء كان في جذر النطاق أو داخل مجلد فرعي (كما هو حال GitHub Pages) دون أي تعديل.

> **مهم:** بعد أي تعديل على ملفات ثابتة (CSS/JS) ونشرها، ارفع رقم `CACHE_VERSION` في `js/config.js` (مثال: من `1.0.2` إلى `1.0.3`) حتى يحصل المستخدمون على التحديث فوراً بدل أن يبقى Service Worker يعرض النسخة القديمة من الكاش (راجع قسم "تحديث التطبيق" أدناه).

## 3) ربط Google Sheets (مزامنة اختيارية — غير إلزامية للتشغيل)

النظام يعمل بالكامل محلياً عبر LocalStorage دون الحاجة لهذه الخطوة. مزامنة Google Sheets طبقة **إضافية اختيارية** فوق ذلك (نسخة سحابية من نفس البيانات)، تُفعَّل فقط عند ملء `CONFIG.SCRIPT_URL`.

### إنشاء Google Apps Script Web App

1. أنشئ ملف **Google Sheets** جديداً فارغاً (أو استخدم ملفاً موجوداً).
2. من القائمة: **Extensions → Apps Script**.
3. احذف أي كود موجود في `Code.gs` الافتراضي، والصق بدلاً منه محتوى الملف `apps-script/Code.gs` الموجود في هذا المشروع بالكامل.
4. (اختياري) عدّل قيمة `SHEET_NAME` أعلى الملف إن أردت استخدام ورقة (Sheet) باسم محدد داخل الملف؛ إن تركتها فارغة سيُستخدم أول ورقة تلقائياً.
5. من أعلى يمين المحرر: **Deploy → New deployment**.
6. اختر النوع **Web app**.
7. اضبط:
   - **Execute as:** Me (حسابك)
   - **Who has access:** Anyone (حتى يستطيع التطبيق الوصول إليه من متصفح المستخدم)
8. اضغط **Deploy**، وامنح الأذونات المطلوبة عند الطلب.
9. انسخ **رابط Web App** الناتج (ينتهي بـ `/exec`).

### ربطه بالمشروع

افتح `js/config.js` وعدّل:
```js
const CONFIG = {
  SCRIPT_URL: "الصق الرابط هنا",   // رابط الـ /exec الذي نسخته
  SHEET_NAME: "",                   // اختياري، يطابق SHEET_NAME في Code.gs
  CACHE_VERSION: "1.0.2"
};
```

بمجرد ملء `SCRIPT_URL`، تبدأ كل عملية حفظ محلية (إضافة/تعديل/حذف موجه أو معهد أو خلية في الخطة) بإرسال نسخة محدَّثة في الخلفية إلى الشيت تلقائياً عبر `js/services/sheetsSync.js`. إن فشل الاتصال (لا إنترنت، خطأ في الرابط، إلخ) يظهر إشعار Toast تحذيري، **دون** أن يتأثر الحفظ المحلي أو عمل النظام إطلاقاً — LocalStorage يبقى دائماً مصدر الحقيقة الأساسي أوفلاين.

**العمليات المدعومة عبر `Code.gs`:** قراءة (`read`) / بحث (`search`) / فرز (`sort`) عبر GET، وإضافة (`add`) / تعديل (`update`) / حذف (`delete`) / مزامنة دفعة كاملة (`bulk_sync`) عبر POST — جميعها بصيغة JSON فقط وبواسطة Fetch API.

## 4) تحديث التطبيق (بعد النشر)

Service Worker (`sw.js`) يخزّن كل الأصول الثابتة للعمل دون إنترنت، ويتحدّث تلقائياً حسب `CONFIG.CACHE_VERSION`:

1. عدّل أي ملف CSS/JS كما تحتاج.
2. ارفع رقم `CACHE_VERSION` في `js/config.js` (مصدر الحقيقة الوحيد لرقم النسخة، يُقرأ من `sw.js` أيضاً عبر `importScripts`).
3. انشر التحديث (git push، فGitHub Pages يحدّث الموقع تلقائياً).
4. عند زيارة المستخدم التالية، يكتشف المتصفح نسخة `sw.js` جديدة، يحمّل كاشاً جديداً بالاسم الجديد، ويحذف الكاش القديم تلقائياً (`activate` event) — التحديث فوري (`skipWaiting` + `clients.claim`) دون الحاجة لإغلاق كل تبويبات التطبيق يدوياً.

## 6) لماذا نمط Namespace (`window.APP.*`) وليس `import/export`؟

تم طلب "ES6 Modules" أصلاً، لكن متصفحات Chrome وFirefox **تمنع** تحميل سكربتات `type="module"` عند فتح الصفحة عبر `file://` مباشرة (قيد CORS في المتصفح نفسه)، وهو ما يتعارض مع اشتراط "التشغيل بالنقر المزدوج دون أي سيرفر". للحفاظ على الهدفين معاً (تقسيم حقيقي للكود + عمل مباشر بالنقر المزدوج)، اعتُمد نمط **Namespace**:
- كل ملف JS مستقل تماماً ومسؤول عن وظيفة واحدة فقط (نفس فلسفة الوحدات الحقيقية).
- كل ملف يُسجّل نفسه داخل كائن عام واحد: `window.APP.اسم_الوحدة`.
- لا تكرار أكواد، ولا حاجة لأي أداة بناء (Webpack/Vite/إلخ) — هذا الاختيار القياسي لتطبيقات "Offline-first" التي يجب أن تعمل بالنقر المزدوج.

كذلك، `fetch()` لملفات HTML محلية عبر `file://` ممنوع بنفس القيد، لذلك كل "صفحة" مضمّنة كقسم (`<section class="page">`) داخل `index.html` نفسه، ويتولى `router.js` إظهار/إخفاء القسم المطلوب فقط دون أي إعادة تحميل.

## 7) المزايا المتوفرة حالياً

- لوحة تحكم بإحصائيات لحظية، بحث سريع، ساعة وتاريخ.
- إدارة كاملة للموجهين والمعاهد (إضافة/تعديل/حذف/بحث/فرز)، مع تحديد نطاق كل موجه.
- شبكة خطة شهرية تفاعلية مع استبعاد عطلة نهاية الأسبوع تلقائياً، وتحقق آلي من التعارضات والأيام الفارغة.
- نسخ خطة الشهر السابق، مسح الشهر/الأسبوع/اليوم.
- تقارير إحصائية، وطباعة احترافية (عامة أفقية + فردية رأسية).
- تصدير JSON/CSV واستيراد نسخ احتياطية (دمج أو استبدال).
- **PWA كامل:** قابل للتثبيت (Install App)، يعمل بالكامل دون إنترنت للصفحات التي زارها المستخدم سابقاً، تحديث تلقائي، Splash/Theme Color، Cache Versioning.
- **مزامنة Google Sheets اختيارية** فوق LocalStorage (قراءة/إضافة/تعديل/حذف/بحث/فرز).
- **وضع داكن/فاتح** قابل للتبديل، مع حفظ التفضيل محلياً.
- إشعارات Toast ونوافذ Modal احترافية بديلة عن `alert`/`confirm` بالكامل، وSkeleton Loading جاهز للعمليات غير المتزامنة.
- تصميم RTL كامل، متجاوب تماماً مع Desktop / Laptop / Tablet / Android / iPhone.
- معالجة شاملة للأخطاء: انقطاع الإنترنت، انتهاء المهلة، فشل Apps Script، أخطاء JavaScript — برسائل عربية واضحة.

## 8) التطوير المستقبلي

بنية `APP.storage` منفصلة تماماً عن واجهة العرض، لذلك يمكن مستقبلاً استبدال أو إضافة أي مصدر بيانات آخر بتعديل `storage.js`/`sheetsSync.js` فقط دون المساس ببقية الوحدات. كذلك يسهل إضافة تسجيل دخول وصلاحيات لاحقاً كوحدة جديدة (`auth.js`) دون إعادة هيكلة.
